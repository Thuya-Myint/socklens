# Snapshots, filters and shell completion

The completion improvements and snapshot save hardening on this branch are not
in v0.12.0. The snapshot commands and filters themselves are available in v0.12.0.

Save a baseline, start your service, then save another observation:

```sh
socklens snapshot save --protocol tcp --port 8080 before.json
# Start your service on port 8080 in another terminal.
socklens snapshot save --protocol tcp --port 8080 after.json
socklens snapshot diff before.json after.json
socklens snapshot diff --json before.json after.json
```

Put options before filenames. Quote paths containing spaces. Use a new filename
for every save: existing files, directories and symlinks are refused. Saves use
a temporary file beside the destination and an atomic hard link to publish the
complete file without overwriting another writer. The destination filesystem
must support hard links (for example NTFS, ext4 or APFS); unsupported filesystems
fail without replacing the destination. Saved socket data can include process
names, PIDs and peer addresses; choose storage you control. Files are created
with owner-only permissions on Unix; Windows directory access rules apply.

Snapshot files have their own version 1 envelope (`version`, `timestamp`,
`sockets`). They are different from `list --format json-v1` output. Diff accepts
regular files up to 32 MiB, rejects unknown fields, incomplete envelopes and
trailing JSON/data, and returns exit 0 when a valid comparison succeeds,
including when changes exist. Compare observations from the same machine:
identities include platform socket identifiers, and observations can miss
connections that appear and disappear between saves.

Filters intersect: every supplied filter must match. For example:

```sh
socklens list --protocol tcp --listening --local-address 127.0.0.1 --port-range 8000-8100 --process python --state LISTEN
socklens snapshot save --protocol tcp --listening --pid 12345 owned-listeners.json
```

Process names are matched as case-insensitive substrings; state is
case-insensitive. Unknown process details cannot match a process-name filter.
Use `socklens COMMAND --help` for the options supported by that command.

Generate the script for your shell after installing a version containing these
changes. The script asks the installed executable for context-aware suggestions,
so regenerate it when upgrading from an older release.

Bash (load in the current session; source the generated file from `.bashrc` to
keep it):

```bash
socklens completion bash > ~/.socklens-completion.bash
source ~/.socklens-completion.bash
```

Zsh (initialize completion before loading; add these lines to `.zshrc`):

```zsh
autoload -Uz compinit
compinit
source <(socklens completion zsh)
```

Fish:

```fish
mkdir -p ~/.config/fish/completions
socklens completion fish > ~/.config/fish/completions/socklens.fish
```

PowerShell 7 (load in the current session; put the generated script in your
profile to keep it):

```powershell
socklens completion powershell | Out-String | Invoke-Expression
```

Only load completion scripts generated by your installed SockLens executable.
Try `socklens snap<Tab>`, `socklens snapshot d<Tab>`,
`socklens list --local-<Tab>`, and `socklens list --protocol t<Tab>`.
Snapshot filenames and `tls --ca-file` use the shell's file completion.
Suggestions do not collect sockets, connect to endpoints, install updates or
terminate processes. Numeric IDs/ports and free-text process names are entered
by the user.
